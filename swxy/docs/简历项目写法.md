**GSK-POC｜企业级智能文档问答 RAG 系统**　`2026.04–2026.06`  
企业级课程项目二次开发｜Python / FastAPI / Elasticsearch / PostgreSQL / Redis / DeepDoc / DashScope / Docker Compose / React / TypeScript

面向企业内部知识检索与问答场景，基于 InfiniFlow/RAGFlow DeepDoc 二次开发，打通“文档解析入库 → Query 处理 → 混合召回 → Rerank → 引用生成 → 会话持久化”的完整 RAG 链路。

- **文档解析与可靠入库：** 为 PDF、DOCX、XLSX、TXT、Markdown、HTML 建立格式路由；PDF 按文本层自动分流，可搜索 PDF 直接抽取文本，扫描件进入 DeepDoc OCR、Layout 与表格结构识别，并通过 `_text_merge`、`_concat_downward` 恢复阅读顺序；以 128 Token 为目标软边界切块，调用 `text-embedding-v3` 生成 1024 维向量，显式创建 ES 向量映射并 Bulk 入库；Bulk 或解析失败时补偿清理磁盘、ES 与 PostgreSQL 中间数据。
- **Query 处理与召回精排：** 对 Query 执行大小写、全半角、繁简、分词、词权重和同义词扩展，以 `weighted_sum` 融合关键词与 Dense Vector；初排近邻上限设为 1024、首轮候选窗口至少设为 128，调用 `gte-rerank-v2` 二次评分并过滤 Top-5；空召回时同步降低 `minimum_should_match` 与向量相似度阈值重试。
- **可追溯流式问答：** 将引用编号、Chunk ID、文档 ID、文档名及正文注入 Prompt，约束 DeepSeek-R1 使用 `##编号$$` 标注依据；通过 `StreamingResponse + SSE` 增量返回思考、答案、引用与推荐问题，引用统一从 1 开始，并将完整问答与引用持久化到会话历史。
- **服务化与工程闭环：** 基于 FastAPI 提供注册登录、知识库、会话、临时文档和流式问答接口；PostgreSQL、Elasticsearch、Redis 分别承担业务持久化、全文/向量检索和 2 小时临时文档缓存；Nginx 代理前端与 SSE，Docker Compose 一键编排五项服务，并以 Mock 模型完成六种永久格式、三种临时格式及权限/事务自动化验收。

## 面试时必须说清

- 项目是基于 InfiniFlow/RAGFlow 的**二次开发与工程整合**，DeepDoc、分词查询和部分 ES 适配不是从零自研。
- “128 Token”是目标切块阈值/软边界，不保证每个 Chunk 恰好 128 Token。
- 检索器支持前三页走 Rerank，但当前业务问答只请求第一页；可表述为“首轮宽召回后精排”，不要声称业务逐页调用三次。
- 当前本地验收使用 Mock Embedding、Rerank、LLM；真实 DashScope 账号和外网调用尚未做最终验收，因此不要声称已经完成线上 SLA 或真实模型压测。
- 六格式 Compose 冒烟中的合成 PDF 带可搜索文本层；扫描件会路由到 DeepDoc，但完整 OCR/Layout 模型推理仍需在目标部署机器复验资源占用，面试时不要声称已完成大规模扫描件压测。
- 项目日期与课程性质应由本人经历佐证，现有 Git 历史不能证明 `2026.04–2026.06`。
